# Upgrading to 12.0.0

## CCK conformance

CCK conformance was bumped from v22 to v26. This brings a host of more conformancy, plus some minor bugfixes

There should not be much in the way of changing to existing logic, except that snippets are now
generated with a corresponding message being fired according to the snippet

## Events

### Refactor of base logic

The events system and base class has been heavily refactored. But none of this should be visible to the user
or effect much existing code. The key thing is the class you inherit from is now `Cucumber::Core::Events::Base` instead
of `Cucumber::Core::Event` if you are writing your own events. Also, you must statically provide the event id
as a method called `event_id` which expects a symbol to be returned. This is to ensure that the event id is always
available and not dependent on code generation.

### Generic refactor of generation logic

Previously events were often generated in 2 ways, and were not consistent. We have made a big effort to generate
events as "close to" their legitimate source as possible. Whilst this hasn't been done for all events, it has been
done for a good portion of them. This work will continue in the v12 lifecycle

## Removed previously deprecated items that were deprecated in v11

### Strict configuration

For a while cucumber was heavily divergent in terms of how it handles "strict" mode - In some places it was a
configuration setting, in others it was a command line flag, and in others it was just a concept that was
handled differently across different formatters

Going forwards strict mode is no more. So any configuration that relies on this will need to be removed

## Newly deprecated items

### `Cucumber::Runtime#ask`

This has not been actively supported and is now deprecated

Should you wish to delay things and/or perform manual checks, use an interactive debugging tool such as the one
built into JetBrains/RubyMine or a gem like `pry`
